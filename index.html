REST API (typical approach)

Often you end up needing multiple endpoints (or custom query params) to return different field combinations.
GET /countries/VN/name-currency GET /countries/VN/name-emoji GET /countries/VN/name-capital
You either create many endpoints, or keep adding special query parameters to control fields.

GraphQL (this demo)

One endpoint, and you request exactly the fields you need by changing the query.
query ($code: ID!) { country(code: $code) { name capital # try: emoji, currency, languages { name } } }
SQL mental model (rough analogy):
SELECT name, capital FROM country WHERE code = $code;
GraphQL is not SQL — the server decides how to fetch data — but the fields you list are like the columns you select.
Same URL every time — only the query changes.
